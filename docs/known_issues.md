## KI-001 侧脸时 `mar` / `ear` 数值爆炸

**样本**：`data/raw/samples/bad_sample_sideface.mp4`（1280×720，29.97 fps，272 帧，人物甩头转身）。

**现象**：

- 第 16–30 帧、第 34 帧：共 16 帧未检出人脸（`face_found=0`）。
- 第 31–36 帧：检测到人脸，但 478 个关键点整体飘到人物左侧背景里。
- 特征表随之爆炸：`mar` 最大 **1.506**、`ear_l` 最大 **1.856**、`ear_r` 最小 **0.006**。
- 抽帧目视确认：叠加视频第 32 帧的黄色关键点落在空背景上，不在脸上。

**复现**：

```powershell
venv\Scripts\python.exe src\extract_landmarks.py --input data/raw/samples/bad_sample_sideface.mp4 --output_dir C:\temp\bad_run
```

查看 `C:\temp\bad_run\features\features.csv` 的 31–36 行。

**原因分析**：

1. 几何特征都是比值：`mar = |y13 - y14| / |x78 - x308|`。侧脸时嘴角横向距离缩小、纵向距离不变，比值被放大。
2. 分母下限设的是 `1e-3`（归一化坐标，1280 px 下约 1.3 px），只能防“两点重合”导致的除零，**防不住“两组点一起偏移”**——此时分子分母同时缩小，比值仍然“看起来合理”，只是数值异常大。
3. `mar` 的截断上限设的是 `2.0`，所以 1.506 被原样保留，没有被裁剪。

**影响**：特征表出现不可信极值，曲线被拉平或误读；如果直接进入 W4 的六项指标，会污染统计量。

**W2 处理计划**（按优先级）：

1. 读取 landmark 的 `visibility` / `presence`（若模型输出提供），低于阈值判为无效帧。
2. 人脸框合理性校验：关键点包围盒的宽高比、面积占比、帧间中心漂移速度，异常则丢弃整帧。
3. 帧间连续性：与前一帧关键点做平均位移，突跳超过阈值判为无效。
4. 时序平滑（中值滤波 / 滑动窗口），并在报告中注明窗口长度。
5. 保留本样本作为回归用例，W2 完成后要求：`mar` 最大值回落到 1.0 以内，且 31–36 帧被标记为无效而不是产生极值。

**明确不做**：单纯把分母阈值从 `1e-3` 调高。正脸小幅张嘴时嘴角距离本身就小，调高阈值会误杀真实表情帧，得不偿失。

## KI-002 分母下限的适用边界

`MIN_DEN = 1e-3` 的设计目标只是**防除零 / 防两点重合**，不是质量过滤器。

- 有效场景：关键点退化成一条线（遮挡、极端角度）时，避免 `x / 1e-9` 式爆炸。
- 无效场景：整组关键点平移或旋转（KI-001），比值仍稳定，门槛不触发。

因此 W2 的质量控制必须放在「关键点层面」（可见性、人脸框、时序连续性），而不是继续在「比值层面」加阈值。
