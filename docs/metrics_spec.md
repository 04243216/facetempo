## 特征可用性实测（W3.1，2026-11-12）

样本：`data/raw/samples/adult_frontal.mp4`（321 帧，25 fps，正脸微笑）。

### 通道筛选

| 通道 | 范围 | 中位数 | 判定 |
|---|---|---|---|
| `mouthSmileRight` | 0.42 – 0.98 | 0.957 | **弃用**：68% 的帧 ≥0.95，饱和 |
| `cheekSquintRight` | 0.00 | 0.00 | **弃用**：全片恒为 0，模型未启用 |
| `mouthUpperUpRight_smooth` | 0.00 – 0.88 | 0.586 | 可用，与 `mar` 的 r = 0.965 |
| `eyeSquintRight_smooth` | 0.39 – 0.71 | 0.513 | 可用，但动态范围小 |
| `smile_lift` | -0.459 – -0.353 | -0.392 | 可用，受张嘴动作混淆 |
| `mouth_width` | 0.392 – 0.546 | 0.488 | 可用，与 `mar` 的 r = 0.656 |

反例存档：`outputs/curves/dynamics_bad_proxy.png`（基于饱和的 `mouthSmile` 得出 640 ms 的伪滞后）。

### 几何代理定义

在**像素坐标**下计算（避免 16:9 归一化坐标的各向异性）：

```
face_width  = ||p234 - p454||                     # 左右脸颊点欧氏距离
eye_mid_y   = (p133.y + p362.y) / 2               # 内眼角中点
mouth_mid_y = (p61.y  + p291.y) / 2               # 嘴角中点
smile_lift  = (eye_mid_y - mouth_mid_y) / face_width
mouth_width = |p61.x - p291.x| / face_width
```

注意：`smile_lift` 按此定义为负值，越接近 0 表示嘴角越上提；但**张嘴会拉低该值**，所以它和 `mar` 的相关只有 0.038。分析时应与 `mouthUpperUp` 交叉验证，不单独使用。

### 滞后分析方法（可复现）

1. 对两条曲线做 **0.5 s 居中滚动中值**（25 fps → 12 帧），抑制眨眼与高频抖动。
2. 逐 lag 计算 Pearson r，搜索范围 ±1 s（±25 帧）。
3. **仅当 r > 0.6 且 |lag| 未触及搜索边界**时，才输出滞后结论；否则标记为弱相关。
4. 事件窗口：以 `smile_lift` 的峰值（75 分位阈值、最小间隔 1.5 s）为中心，前后各取 1.5 s。
5. 符号约定：`lag > 0` 表示眼周落后于嘴角，`lag < 0` 表示眼周领先。脚本内置合成信号自检（已知滞后 5 帧 → 必须还原 +5）。

### 本样本结果

| 范围 | 滞后 | 相关 r | 结论 |
|---|---|---|---|
| 全片（`mouthUpperUp` vs `eyeSquint`） | -4 帧（-160 ms） | 0.618 | 有效，眼周略领先 |
| 事件 @29（起势段） | +18 帧（+720 ms） | 0.942 | 眼周明显滞后 |
| 事件 @150 | — | 0.588 | 弱相关，且撞搜索边界，无效 |
| 事件 @193 | -4 帧（-160 ms） | 0.828 | 接近同步 |
| 事件 @235 | -3 帧（-120 ms） | 0.961 | 接近同步 |

解释与限制：

- 持续微笑段（@193、@235）眼周领先 120–160 ms，接近同步，符合杜兴微笑“眼周与嘴角同期或略先行”的预期。
- 第一段起势（@29）眼周滞后 720 ms，可能是嘴角先动、眼周随后收紧，也可能受窗口边缘影响；需要更多样本确认。
- 相邻事件窗口存在重叠（112–188 与 155–231），事件间不完全独立。
- 单样本、13 秒素材，**不能外推到真人/AI 总体结论**；W4–W6 需在 `real/` 与 `ai/` 两个数据集上重复该流程。

### 使用规则

- 任何滞后结论必须同时给出 **r 值、样本片段与 fps**，禁止只报毫秒数。
- 跨视频比较时统一：相同 fps、相同平滑窗口、相同搜索范围。
- Blendshape 系数的绝对值不作为强度指标；只用其动态变化与相关性。

## W4 干净队列实测（2026-11-13）

样本：`data/raw/samples/w4_clean/`（3 条真人 + 2 条 AI），产物隔离在 `outputs/w4_clean/`。5 条全部 100% 人脸覆盖，**覆盖率门控无误杀**。

| 视频 | 类型 | r | lag | 有效 | 起势/维持 |
|---|---|---|---|---|---|
| `real_01_two_smiles` | 真人（持续微笑） | 0.575 | +1000 ms（撞边界） | 否 | n/a |
| `real_02_two_smiles` | 真人（大笑仰头） | 0.652 | +1000 ms（撞边界） | 否 | n/a |
| `real_03_fake_smile` | 真人假笑 | **0.273** | +360 ms | 否 | INCONSISTENT（-620 ms） |
| `ai_smile_01` | AI | 0.623 | +333 ms | 是 | n/a（单次笑） |
| `ai_smile_02` | AI | 0.789 | -1000 ms | 是 | n/a（单次笑） |

### 一阶差分补充分析

为去除慢趋势，对 0.5 s 平滑后的两条曲线做一阶差分，再算互相关：

| 视频 | 原始 best r | 差分 best r | 差分 lag |
|---|---|---|---|
| `real_01_two_smiles` | 0.683 | 0.234 | +15 f |
| `real_02_two_smiles` | 0.665 | 0.163 | +20 f |
| `real_03_fake_smile` | **0.273** | **0.084** | +2 f |
| `ai_smile_01` | 0.623 | 0.448 | +9 f |
| `ai_smile_02` | 0.789 | 0.205 | -20 f |

### 结论（必须按此口径写报告）

1. **假笑是当前唯一稳定可分的方向**：无论原始相关（0.273）还是一阶差分（0.084），`real_03_fake_smile` 都显著低于另外 4 条；且起势与维持阶段滞后差 620 ms（INCONSISTENT）。这与“假笑缺乏眼嘴联动”的预期一致。
2. **但不能宣称“AI 相关性更低”**：AI 的 0.623 / 0.789 与真人自然笑的 0.575 / 0.652 完全重叠。若写“AI 肌肉割裂导致 r 低”，属于过度解读。
3. **两条真人素材名不副实**：`real_01` 实际是持续保持的微笑（不是两次独立微笑）；`real_02` 是大笑仰头，嘴几乎全程张开（`mar` 0.36–1.18）、头部运动大。二者都不满足“固定机位、两次独立微笑”的受控条件。
4. **滞后估计频繁撞 ±1 s 边界**（`real_01`、`real_02`）：说明 1 s 搜索窗对慢起势不够，或存在未被去除的慢趋势。差分后滞后缩到 2–20 帧，但相关性同时下降，说明“慢趋势”既贡献了相关也贡献了伪滞后。
5. **质量门控表现**：覆盖率门控没有误杀；r/边界门控把 3/5 标为不可靠，与素材体检（运动量、眼通道一致性、嘴部动态）一致，属于正确拒绝而非误杀。

### 下一步（W4.1 待做）

   - 画面运动量（帧差）< 2.0；

   - `mouthUpperUpRight_smooth` 标准差 > 0.05（嘴部必须有动态）。
2. 换用“嘴角相对嘴唇中心线”的垂直位移作为微笑代理，隔离下颌开合的影响。
3. 事件级分析：每个微笑事件减事件前 1 s 基线，单独算 lag/r，并用自助法给 95% 置信区间；组间比较看分布。

## W4.1 微颤（Jerk）指标与门控实测（2026-11-13）

### 方法

- 使用**原始信号**（不叠加额外平滑）：一阶差分均值 = 速度，二阶差分均值 = Jerk，均按 fps 归一化。
- **归一化 Jerk = Jerk / (std × fps²)**：去掉动作幅度的影响，才是真正的“平滑度”。
- 高频能量占比：去线性趋势后，5–12 Hz 能量 / 0.5–12 Hz 总能量。
- 事件级：事件前 1 s 均值作为基线扣除；对每个事件的 r 做 1000 次 Bootstrap，给 95% CI。
- 三道硬门控：画面运动量 < 2.0、几何眼通道与 Blendshape 眼通道相关 < -0.5、`mouthUpperUp` 标准差 > 0.05。

### 归一化微颤结果

| 视频 | 类型 | 嘴部 std | 归一化 Jerk（嘴） | 归一化 Jerk（眼） | 眼周高频能量 | 门控 |
|---|---|---|---|---|---|---|
| `ai_smile_01` | AI | 0.274 | 0.021 | **0.064** | 0.022 | 通过 |
| `ai_smile_02` | AI | 0.079 | 0.022 | **0.086** | 0.049 | 通过 |
| `real_01_two_smiles` | 真人 | 0.278 | 0.078 | **0.332** | 0.058 | 误杀（眼通道 +0.44） |
| `real_02_two_smiles` | 真人 | 0.235 | 0.161 | **0.324** | 0.082 | 误杀（运动量 5.04） |
| `real_03_fake_smile` | 真人假笑 | 0.007 | 0.080 | **0.110** | 0.030 | 误杀（嘴部动态 0.008） |

### 关键发现

1. **裸 Jerk 会被动作幅度污染**：假笑嘴部几乎不动（std = 0.007），裸 Jerk 0.38 看起来“最平滑”，归一化后 0.080，与真人持平。必须用归一化 Jerk，否则会把“没动”误判成“太顺滑”。
2. **归一化后，眼周微颤是目前最好的判别特征**：真人自然笑 0.332 / 0.324，AI 0.064 / 0.086，相差约 **3.8–5 倍**；假笑 0.110，介于两者之间但更靠近 AI。
3. **高频能量方向一致**：真人眼周 0.058 / 0.082，AI 0.022 / 0.049，假笑 0.030。
4. **三道门控在这批数据上误杀了全部 3 条真人**，两条 AI 反而全部通过：
   - `real_01`：静态保持微笑时眼通道相关为 +0.44（低方差下相关不稳定，且几何/Blendshape 通道不一致）；
   - `real_02`：大笑仰头，画面运动量 5.04；
   - `real_03`：假笑幅度小，嘴部动态 0.008。
   这说明门控对“静态、干净、平滑”的素材有偏，**不能原样用于真人/AI 对照**。
5. **结论**：归一化眼周微颤（配合高频能量）是当前最有希望的判别方向；相关性 r 与滞后仍不足以单独区分。

### 门控修订方向（W4.2）

- 运动量改用**头部姿态 / 人脸框中心位移**，不再用全画面帧差（表情本身也会增加帧差）。
- 眼通道一致性增加**最小方差前提**；低方差时该门控不生效。
- 嘴部动态阈值不适用于假笑素材，应改为“事件内存在可检测的微笑代理变化”，而不是固定 std。
- 用分布检验（置换检验 / Mann-Whitney）比较组间归一化 Jerk，不再比较单条数值。

## W4.4 统一帧率 + 独立盲测（2026-11-13）

### 方法修正（两处必须记录的错误）

1. **帧率混杂**：`real_clean_05` 为 59.9 fps，其余 24–25 fps。此前直接按各自帧率计算，60 fps 的逐帧二阶差分天然更小，导致该样本被系统性压低。现在所有信号统一线性重采样到 **25 fps** 后再计算。
2. **归一化公式错误**：原写法 `jerk / (std × fps²)` 多除了一次 fps²，使结果强烈依赖采样率。正确写法为 **`jerk / std`（单位 1/s²）**；在统一帧率下，它与幅度无关、与采样率无关。
3. 置换检验改为小样本**精确枚举**（组合数 ≤ 200000 时），p 取精确值；4v4 的下限为 1/70 = 0.0143。

### 主队列 4v4（`real_clean_02–05` vs `ai_clean_01–04`）

|---|---|---|

- 高频能量 p = 0.0429（次要指标，同样显著但效应较弱）。
